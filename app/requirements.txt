# and the annotator's torch stack lives in its separate venv, pinned in
# requirements-annotator.txt (see install.sh / install.ps1).

# Exact pins, not floors: this file used to carry lower bounds so a newer
# interpreter could find a newer wheel (pydantic 2.10's pydantic-core has no
# 3.14 wheel and pip fell back to building it from Rust - a 125-line PyO3
# error). That's still true, but an open-ended `>=` also means "whatever pip
# feels like today", and a shipped installer should not silently pick up an
# untested version. These exact versions are the ones VERIFIED installing as
# wheels on Python 3.12 (this machine's app/core venv, 2026-09-14). Bumping
# any of them is an intentional edit, not something pip decides for you.
#
# install.sh additionally passes --only-binary=pydantic-core. That is scoped on
# purpose: it is the one dependency here that invokes a compiler, and a blanket
# --only-binary=:all: would wrongly reject proxy_tools, a pure-Python sdist
# pywebview needs.
